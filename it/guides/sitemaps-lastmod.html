Sitemap e lastmod: segnalare le modifiche reali

Una sitemap aiuta i crawler a trovare gli URL importanti. Date <lastmod> accurate possono indicare quando una pagina è cambiata davvero.

Da ricordare

Una sitemap suggerisce dove cercare, ma non garantisce scansione, indicizzazione o posizionamento.

Cosa può fare una sitemap

Una sitemap XML elenca gli URL che vuoi far scoprire a un motore di ricerca. È utile per nuovi siti, raccolte di molte pagine e migrazioni. Può anche indicare quando ogni URL ha ricevuto l’ultimo aggiornamento significativo.

Non è un ordine per indicizzare tutte le pagine elencate: i motori decidono autonomamente. Inserisci URL pubblici, accessibili, preferiti e indicizzabili, evitando versioni di staging e duplicati superflui.

Un esempio XML semplice

Questa è una sitemap minima con due pagine. Sostituisci URL e date d’esempio con quelli realmente pubblicati.

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/guides/canonical-urls.html</loc>
    <lastmod>2026-11-17</lastmod>
  </url>
  <url>
    <loc>https://example.com/it/guides/canonical-urls.html</loc>
    <lastmod>2026-11-17</lastmod>
  </url>
</urlset>

<loc> contiene l’URL; il tag facoltativo <lastmod> indica l’ultima modifica significativa di quella pagina, non quando è stato rigenerato il file sitemap.

Quando aggiornare lastmod?

Google può usare lastmod quando le date sono sistematicamente accurate e verificabili. Modifiche al contenuto principale, ai dati strutturati o ai link importanti sono generalmente significative.

  • Aggiornalo: quando riscrivi una guida, cambi informazioni importanti su un prodotto o aggiungi dati strutturati utili.
  • In genere non cambiarlo: per il nuovo anno nel copyright o una ricompilazione senza modifiche reali.
  • Evita di mettere la data odierna ovunque: il segnale rischia di diventare poco affidabile.
Altri tag della sitemap

Google ignora i valori XML di <priority> e <changefreq>. Non servono a imporre una scansione più rapida.

Pubblicare e verificare la sitemap

  1. Crea un file XML con gli URL canonical pubblici che desideri far scoprire.
  2. Pubblicalo a un indirizzo stabile, per esempio https://example.com/sitemap.xml.
  3. Puoi segnalarlo in robots.txt con Sitemap: https://example.com/sitemap.xml.
  4. Per un sito che gestisci, invia l’URL nella sezione Sitemap di Google Search Console.
  5. Aggiorna il file quando aggiungi, rimuovi o modifichi in modo rilevante le pagine.

L’acquisizione corretta della sitemap significa che il file può essere letto; non che tutte le pagine siano state indicizzate.

E per le pagine in più lingue?

Le versioni inglese e italiana, pubblicate su URL diversi, dovrebbero essere raggiungibili tramite link normali. Le rispettive canonical devono indicare l’URL preferito per ogni lingua. Puoi includere entrambe le pagine nella sitemap e descrivere le traduzioni tramite hreflang reciproci nell’HTML.

Per approfondire consulta la guida alle canonical e quella sui ritardi degli aggiornamenti. Local Inspector controlla la pagina attiva, ma non sostituisce la convalida della sitemap o Search Console.
