Canonical URLs: choose the right version

After a redesign, one wrong canonical can tell search engines that a perfectly valid new page is merely a copy of another URL.

Read guide ↓← Back to guides
Key takeaway

A canonical is a strong hint about your preferred URL — not an instruction Google must obey.

What a canonical URL actually means

Several URLs can show the same or very similar content: tracking parameters, category filters, HTTP/HTTPS alternatives or old page routes. A canonical URL indicates which version you prefer search engines to treat as the main representative.

In the HTML <head>, a typical self-referencing canonical looks like this:

<link rel="canonical" href="https://example.com/services/">

Google considers this a strong signal, but it can select a different canonical based on the content and other signals.

How the signals compare

SignalTypical purposeImportant caveat
Permanent redirectMove an obsolete URL to its replacementUsers and bots leave the original URL
rel="canonical"Indicate the preferred URL among similar pagesA strong hint, not a guarantee
XML sitemapList preferred pages for discoveryA weaker canonical signal
noindexExclude a page from searchNot a substitute for canonical selection

Canonical mistakes after a redesign

  • Every new page points to the homepage. Product, service or article pages may be treated as duplicates of an unrelated destination.
  • A staging hostname remains in production. A canonical such as staging.example.com can send an unintended preference signal.
  • Old and new URLs disagree. Redirects, internal links, sitemaps and canonicals should point consistently to the preferred version.
  • Language versions point at one language. For separately translated English and Italian pages, use self-referencing canonicals and reciprocal hreflang links, rather than canonicalizing Italian content to English.
  • The preferred URL returns an error. Verify it loads and contains the intended content.

For an English/Italian website

Suppose you publish a full English guide and its Italian translation on separate URLs. Each page should generally declare itself canonical; hreflang then identifies the alternatives for language targeting.

<link rel="canonical" href="https://example.com/guides/topic.html">
<link rel="alternate" hreflang="en" href="https://example.com/guides/topic.html">
<link rel="alternate" hreflang="it" href="https://example.com/it/guides/topic.html">

The Italian page should use its own Italian URL as canonical and list the same two alternatives. That is how these ReIndexMe guides are configured.

A short canonical audit

  1. Open a representative page from every redesigned template.
  2. Inspect its canonical href; confirm it is an absolute URL for the intended page.
  3. Check the canonical target loads and does not unexpectedly redirect elsewhere.
  4. Verify internal links and sitemap URLs are consistent with that preference.
  5. For sites you manage, use Search Console URL Inspection to compare your declared canonical with Google-selected canonical.

ReIndexMe Local Inspector helps you spot the canonical declared in the active page. It cannot tell you which canonical Google ultimately selected, and it cannot certify crawlability.
