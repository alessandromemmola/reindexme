Sitemaps and lastmod: signal real changes

A sitemap helps crawlers discover your important URLs. Accurate <lastmod> values can help communicate when a page really changed.

Read guide ↓← Back to guides
Key takeaway

Sitemaps suggest where to look; they do not guarantee crawling, indexing or rankings.

What a sitemap can and cannot do

An XML sitemap lists URLs you want a search engine to discover. It is especially helpful for new sites, large collections and site migrations. It can also convey the date of the last significant update to each listed URL.

A sitemap is not a command to index everything it contains. Search engines still decide which pages to crawl and index. Put your preferred, accessible, indexable URLs in the sitemap rather than staging URLs or unnecessary duplicates.

A small XML example

Below is a simplified sitemap for two pages. Replace these example URLs and dates with your own real values.

<?xml version="1.0" encoding="UTF-8"?>
<urlset xmlns="http://www.sitemaps.org/schemas/sitemap/0.9">
  <url>
    <loc>https://example.com/guides/canonical-urls.html</loc>
    <lastmod>2026-11-17</lastmod>
  </url>
  <url>
    <loc>https://example.com/it/guides/canonical-urls.html</loc>
    <lastmod>2026-11-17</lastmod>
  </url>
</urlset>

The <loc> contains the page URL. The optional <lastmod> indicates when that page last had a meaningful update; it is not the time you regenerated the sitemap.

When should lastmod change?

Google says it may use lastmod when the dates are consistently and verifiably accurate. Changes to the page's main content, structured data or important links can count as significant changes.

  • Update it: after materially rewriting a guide, changing a product description or adding important structured data.
  • Usually leave it alone: for a site-wide copyright-year update or merely rebuilding files with no substantive page change.
  • Do not use today's date for every URL: this can make the signal untrustworthy.
Other sitemap tags

Google ignores XML sitemap <priority> and <changefreq> values. Neither setting can force a faster crawl.

Publishing and verifying a sitemap

  1. Generate an XML file containing the canonical, public URLs you want discovered.
  2. Serve it at a stable location such as https://example.com/sitemap.xml.
  3. Optionally reference it from your robots.txt file using Sitemap: https://example.com/sitemap.xml.
  4. For a site you control, submit its URL in Google Search Console's Sitemaps section.
  5. Keep the file updated when important pages are added, removed or meaningfully changed.

A successful sitemap submission confirms that the file could be processed; it does not mean that every listed page was indexed.

What about pages in different languages?

English and Italian versions on separate URLs should each be available through crawlable links. Their canonical declarations should match their preferred language-specific URLs. You can include both pages in the sitemap and use reciprocal hreflang annotations in the HTML to describe the translations.

For the wider picture, review the canonical URL guide and the update-delay guide. Local Inspector can review signals in the active page, but it is not a replacement for sitemap validation or Search Console.
